## 1. 目的と対象
福岡市で活動する社会人バスケサークル OWN PACE の公式サイト。
気軽に参加できる雰囲気を伝え、開催日程の確認と公式LINE経由の参加予約へ導く。
バスケの基本ルールを理解し、ゲーム形式でプレーできる人を対象。経験や技量より協調性を重視。
参加費は1回300円、現金またはPayPay。

## 2. デザイン基準
最重要のビジュアル基準：references/OWN_PACE_LINE_richmenu_reference.jpeg
- 実写感のある夕焼け、海、屋外バスケットゴール、深いブルーとオレンジの光。
- 写真のリアルな空気感を優先。単純なCSS図形やSVGのゴールで置き換えない。
- 既存のOWN PACEロゴを使用。ロゴを生成・描き直ししない。ロゴ実ファイルは別途Work側で確認。
- 細い白い罫線、英字主体の見出し、オレンジのアクセント曲線、十分な余白。
- 「日本の80年代アニメ風」や「過度なグラフィティ」には寄せない。
- 画像に文字やロゴを焼き込まず、HTMLのテキストと既存ロゴを重ねる。
- 今回の images/ は生成コンセプトボードからの切り出し。画質と構図に制約があり、正式な高解像度Web画像への差し替え候補。参照画像と同じものではない。
- REPORTには実際の活動写真のみを掲載。サンプル画像を実活動として扱わない。

## 4. HOME 固定スクロール（03〜07）
- GSAP + ScrollTrigger の pin / scrub を使用し、ひとつの固定エリアとひとつの管理タイムラインで制御。
- スクロール進行に合わせて背景写真そのもの・柄・文字・グラフィックをシーン単位で切り替えてよい。単純な色変更に限定しない。
- 写真はクロスフェード、緩やかなスケール、パララックス等。実写感を損なう過剰な変形は避ける。
- 各シーンのテキストは1画面に収める。収まらない場合は文章を短縮する。詳細は下層ページへ。
- ボタンはクリック可能にし、切り替え途中で誤操作を誘発しない。
- FAQ以降に固定スクロールを持ち越さない。FINAL CTAは最後。
- スマホではシーン数を維持しつつスクロール距離や演出を簡略化してよい。
- GSAP未読込・prefers-reduced-motionの場合も本文・リンクにアクセスできる代替表示を実装。

## 6. 下層ページ
SCHEDULE：Googleカレンダーをページ上部に表示。開催情報と参加導線。埋め込み用カレンダーIDは既存プロジェクトから確認し、タイムゾーン Asia/Tokyo を使用。イベントの予約残席等はGoogleカレンダー単体では自動連携しないため、初期版は実装可能な表示のみ。
RULES：協調性、基本ルール理解、ゲーム形式、参加予約、300円（現金/PayPay）、キャンセルは期限なしだが早めの連絡、無断欠席不可、準備運動、施設マナー、ハラスメント禁止。けがの自己管理と運営側の法的責任を混同しない。活動写真はWeb/Instagram掲載の可能性あり。写りたくない場合は事前申告、掲載後の削除相談にも対応。
RANK：LINE公式アカウントのショップカード登録が必要。REGULAR 5回、ALLSTAR 10回、LEGEND 25回、GOAT 50回。特典の詳細、特典の確認場所への言及も一切記載しない。
REPORT：実際の写真・レポートのみ。実績ゼロ時は準備中の空状態をデザイン。
下層は通常スクロール。見出し・カードのフェードイン、背景の緩やかな動き、軽いホバー演出程度。

## 7. 技術・ファイル設計
- HTML + SCSS + Vanilla JavaScript。React / Three.js は不要。
- GSAP + ScrollTriggerを主軸。Swiper、Lenisは必要な場合のみ追加。
- SCSSはページ別、さらにセクション別の部分ファイル。JSは機能単位。画像はassets/img以下。
- 推奨：src/scss/home/_hero.scss, _next-game.scss, _pinned-story.scss, _faq.scss, _final-cta.scss; src/js/home/pinned-story.js 等。
- SCSSをビルドしてGitHub Pagesへ公開。ビルド手順をREADMEに明記。
- PC基準1920px、コンテンツ最大幅約1360px、ブレークポイント720px・480px。中間幅も流動的に対応。
- FVは100svhを基本に、モバイルブラウザの表示領域変動を検証。
- パフォーマンス：適切な画像サイズ・WebP/AVIF、遅延読込（FV除く）、幅高さ指定、transform/opacity中心、ScrollTrigger.refreshの適切なタイミング。
- アクセシビリティ：キーボード操作、フォーカス可視化、FAQ aria-expanded、十分なコントラスト、reduced-motion、代替テキスト。
- SEO：title/description、OGP、canonical、sitemap、robots、必要に応じて構造化データ。
- GA4/GTM/GSC：実際の測定IDと所有権確認情報はユーザー提供後に設定。CTAイベントの測定設計を用意。
- GitHub PagesにAPIキーや秘密情報を配置しない。
